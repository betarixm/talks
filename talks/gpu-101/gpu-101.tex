  첫 그림은 변환된 정점과 삼각형의 연결입니다. 선은 설명용 표시이며 GPU가 선 그림을 먼저 저장한다는 뜻은 아닙니다. Rasterizer는 삼각형이 덮는 샘플 위치에 프래그먼트를 만듭니다. 두 번째의 칸은 크게 표시했고, 진한 칸에는 여러 삼각형의 후보가 겹쳐 있습니다.

  이것은 논리적 순서이며 실제 GPU는 깊이 검사를 일찍 하기도 합니다. 이제 정점과 표면색의 공식을 직접 바꾸고 싶다면 하드웨어가 어떻게 달라져야 할지 보겠습니다.}

__global__ void add(
    const float* a,
    const float* b,
    float* c,
    int element_count

    int index = blockIdx.x * blockDim.x

    if (index < element_count) {

}

  그 사이 각 thread의 값은 레지스터에 보관됩니다. 실행 상태를 유지하면서 준비된 일을 고르는 것, 이것이 SM에 레지스터와 스케줄러를 연산기 가까이 둔 이유입니다.}

  그 사이에 GPU가 활용하던 성질 자체가 사라진 것은 아닙니다. 많은 데이터에 같은 계산을 적용한다는 일은 계속 같았습니다. 달라진 것은 계산을 시키기 위해 그림을 그리는 척할 필요가 없어졌고, 그 일을 표현하는 도구와 실제로 처리하는 하드웨어가 함께 발전했다는 점입니다. AI가 요구하는 행렬 계산과 데이터 이동은 Tensor Core와 HBM 같은 자원의 발전으로도 이어졌습니다. CUDA의 라이브러리와 컴파일러는 그 기능을 사용자의 코드에 연결합니다. 오늘 본 thread와 block, warp와 SM은 그 한 줄과 실제 계산기를 연결하는 언어입니다. GPU를 다음에 사용하실 때 이 구조를 떠올릴 수 있으면 좋겠습니다. 감사합니다.}
\end{frame}
